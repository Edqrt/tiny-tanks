# TINY TANKS 操作・開発ガイド

起動・ビルド・公開方法は [README](../README.md) を参照してください。以下のパスはリポジトリルートを基準にしています。

## 操作

右上の音量バーでBGMと効果音をまとめて0〜100%に調整できます。初期値は33%で、変更した値はブラウザに保存されます。「♫ / ♪」でミュートを切り替えても設定音量は保持されます。BGMはオリジナル曲「小さな戦車の行進」（Dマイナー、120 BPM、8小節）です。Master Modの楽器の担当と22種類の編成を参考に、旋律・和声・ベース・打楽器の音符は一から作曲しています。音色は付属SoundFontのサンプルを使います。残存する敵の優先度は低い順に brown → gray → teal → yellow → pink → purple → green → white → black です（ゲーム内部では gray は `grey`、pink は `red`）。最優先種と全残存敵の台数でバリエーションを選び、用意された最大台数を超える場合は最後のバリエーションを使います。Blackは台数によらず固定です。一時停止・非表示・撃破・クリア・サウンドOFFでBGMを停止します。

曲の音符は `src/music-score.js` に記述しています。コード進行は Dm → Dm/A → Gm → A7 → Dm → B♭ → Gm・A7 → Dm・A7 です。旋律は2小節ずつの「問いと返し」を組み合わせ、冒頭のモチーフを高くして繰り返し、後半で冒頭へ戻ってから終止します。音価とベロシティは音ごとに指定し、短い助走・強調する音・語尾の休符を使い分けています。チューバとバスドラムは安定した拍を作り、ティンパニは裏拍を補います。チャイムは和声を薄く支え、Sawtoothは主旋律の3オクターブ下を控えめに重ねます。`node scripts/export-original-music.mjs` でBlack編成を `artifacts/audio/music-original.mid` に書き出せます。このMIDIも付属SoundFont用のプログラム番号を使います。

ミッション開始・次ミッション・再出撃時は、オリジナル曲の冒頭2小節のスネアだけを4秒間再生してから本編へ移ります。刻み・強弱・音価・音量は本編の譜面を直接共有し、スネアの作曲を変更するとイントロにも反映されます。スネアは2小節で完結するフレーズを繰り返し、最後の強い一打と休符から本編の頭へつなぎます。イントロ中はプレイヤーを含む全タンクの移動・砲塔回転・射撃・地雷設置とAIの時間経過を停止します。白タンクも表示したままにし、操作解禁時に不可視へ移ります。サウンドOFFでも待機時間は同じです。一時停止ではイントロの進行も止まり、再開時に最初からやり直しません。

### 楽器の担当とリファレンスへの対応

出典は[BigKitty1011の配布動画](https://www.youtube.com/watch?v=MV3aX8Cwb40)からリンクされたMIDI・SoundFont・MuseScore譜面です。原本は `references/master-mod/` に保存しています。`arrangements.json` には小節位置・楽器別の発音数・音域・ゲームとの対応を記録しています。

リファレンスでは全22編成でピッコロの138音のフレーズが共通です。敵が強くなっても主旋律を別の楽器に置き換えず、伴奏の組み合わせとパターンで変化させます。発音数は配布MIDIのnote-onに基づき、トレモロなどの表記を含む譜面上の音符数とは区別しています。以下の分析を新曲の楽器の担当に反映しています。表内の発音数はリファレンスの値です。

| 楽器 | 分析した担当 | 実装への反映 |
| --- | --- | --- |
| Piccolo | 共通の主旋律。細かな三連符と短い音が中心 | 全編成で同じパートを維持。音色を優先度で交換しない |
| Snare Drum | 行進曲らしい刻みとロール。弱打・強打を使い分ける | Masterの「三連符でクレッシェンド→裏拍の強打→軽い刻み」を参考に作曲。2小節の最後は強打と休符で完結。サンプルの自然減衰を使用 |
| Timpani | 音程のある低音とロール。疎な18音／密な34音の主要パターンがある | 台数別にパターンを交換。バスドラムと別の楽器として再生 |
| Bass Drum | 音程を動かさない低域のアクセント | 専用サンプルで、新しい低域のアクセントを再生 |
| Cymbal | 長めの余韻で拍を強調するアクセント | ハイハットで代用せず、付属のシンバルサンプルを使用 |
| Triangle | 短い音と長い音を交互に鳴らす、裏拍中心の刻み | 2種類のサンプルで新しい裏拍のパターンを再生 |
| Tuba | 短い低音で和声とリズムを支える伴奏。MIDI音高21〜31 | 新しいコード進行に沿う独立したベースパートを使用 |
| Chimes | 長い音を重ねて和声と響きを加える24音のパート | 新しい和声でGreenとBlackに追加。主旋律の代替にはしない |
| Sawtooth | 114音すべてが同時刻のピッコロの3オクターブ下に一致する、主旋律の補強 | 新しい主旋律をWhiteとBlackで重ねる |
| Fanfare | 開始時の別の効果音用パート | 戦闘BGMのループから除外 |

### リズムと音程の実測分析

現在の主旋律は、三連符の助走を「拍頭の音→0.25拍位置の接近音→0.5拍位置の着地」に変更し、16分音符2つで助走します。Sawtoothも同じタイミングです。以下のMaster実測値は比較資料として保持し、スネアとティンパニのロールは維持しています。

`python scripts/analyze-music-rhythm.py` で、各楽器が最初に現れるバリエーションの8小節を解析できます。発音位置・ゲート長・音高・強弱・全音符データは `references/master-mod/rhythm-analysis.json` に保存しています。以下の拍数は四分音符を1拍とし、120 BPMで1拍＝0.5秒です。「0.5拍位置」は8分音符の裏拍を表します。

| 楽器 | Masterで実測したリズム・音程 | 新曲への反映 |
| --- | --- | --- |
| Piccolo | 138発音。裏拍64音・表拍42音に、三連符や16分音符を加える。主要ゲートは約0.25拍、三連符の助走は約0.08拍。弱い和声音も同時に重なる | 元の旋律の輪郭を保持し、ゲートを最大約0.25拍に短縮。助走・半音進行・折り返しに加え、弱い和声音を配置 |
| Snare | 単一音高26。0→1/6→1/3→0.5拍のロールを弱→中→強へクレッシェンド。通常打は約0.25拍、ロールは約1/6拍 | このロールと強弱の関係を採用。2小節の最後は強打と休符で完結し、イントロと本編で共有 |
| Timpani | 疎な編成では18音。0.125拍間隔の導入ロールの後、0.5拍位置から約2拍の長音。MIDI音高31・34・38を中心に、4小節周期で休む | ロール・長い低音・空白を区別。新曲ではDマイナーのA・D・F、B♭和音ではF・D・B♭へ対応。密な編成は刻みを増やす |
| Bass Drum | 20打すべて裏拍。2小節の主な発音位置は0.5・2.5・4.5・5.5・6.5拍。音高24で固定 | 同じアクセント位置をシンバル・チャイムと共有。表拍のキックを撤去 |
| Cymbal | 20打すべて裏拍。バスドラムと同じ発音位置。音高43で固定し、約1〜2拍の余韻を持つ | キックと発音を揃え、長さを変えてアクセントを補強 |
| Triangle | 全32打が裏拍。音高21と22を交互に使う。同じ高さの旋律ではなく、短音・長音のサンプルを選ぶ番号 | 0.5・1.5・2.5・3.5拍の交互打を維持。ゲートと強弱を揃える |
| Tuba | 46音のうち32音が裏拍。全音のゲートは約0.25拍。根音・和声音のほか、半音下からのアプローチも含む | 表拍の単純な根音・5度反復をやめ、裏拍で和声音を動かす。DmならD・F・A、A7ならA・C♯・E・Gを使い、フレーズ頭に半音の助走 |
| Chimes | 24音すべて裏拍。約1〜5拍の長音を重ねる。MIDI音高67〜75の有音程パート | キックと同じ位置から長い和声音を重ねる。新曲の和声が変わる直前には音を切る |
| Sawtooth | 114音すべてがピッコロの同時刻の音の3オクターブ下。主要ゲートも一致。弱い和声音の一部は含まない | 装飾を含む主旋律を3オクターブ下で同時に再生。追加した弱い和声音は重ねない |

| Brown／Bronze | Piccolo・Snare | 変更なし | 変更なし | 変更なし |
| Gray／Silver | Piccolo・Snare・Triangle | Timpani追加 | 2台と同じ | 2台と同じ |
| Teal／Sapphire | Piccolo・Timpani・Cymbal・Triangle | Snare追加 | 2台と同じ | 2台と同じ |
| Yellow／Citrine | Piccolo・Timpani・Bass Drum・Cymbal・Triangle | Snare追加 | Timpaniを密なパターンへ | 3台と同じ |
| Pink／Ruby | Piccolo・Timpani（密）・Snare | Cymbal追加 | Triangle追加 | 3台と同じ |
| Purple／Amethyst | Piccolo・Timpani・Cymbal・Tuba | Snare・Bass Drum追加 | Triangle追加、Timpaniを密なパターンへ | 3台と同じ |
| Green／Emerald | Piccolo・Chimes・Timpani・Cymbal・Tuba | Bass Drum追加 | Snare・Triangle追加 | Timpaniを密なパターンへ |
| White／Gold | Piccolo・Timpani・Snare・Sawtooth・Tuba | Bass Drum・Triangle追加、Timpaniを密なパターンへ | Cymbal追加、Timpaniの別パターン | 3台と同じ |

宝石名とゲーム内の種類は色から対応させています。譜面内の掲載順はRuby→Citrineですが、ゲームの切り替え優先度はユーザー指定のYellow→Pinkを採用しています。異種混在時の台数は全残存敵の総数として扱います。MIDI単体にゲームの切り替え条件は含まれていないため、これらは再生側のルールです。

リファレンスの抽出は `python scripts/import-master-music.py` で再実行できます。配布MIDIの音符は `references/master-mod/reference-score.js` に保存し、作曲した `src/music-score.js` は上書きしません。`src/music-bank.js` には音域別・強弱別のサンプルとエンベロープを生成し、`src/music.js` が新曲を同じ拍のまま切り替えます。SoundFont専用のプログラム番号を使用しており、GM音源の楽器番号として解釈しません。SoundFontのリバーブとモジュレーターは再現せず、一部サンプルの離鍵後のループ処理は近似しています。音源はJavaScriptへ埋め込むため、HTMLの直接起動でも再生できます。

| 入力 | 操作 |
| --- | --- |
| WASD / 矢印キー | 移動 |
| マウス | 照準 |
| 左クリック・長押し | 砲弾を発射 |
| Space | 地雷を設置 |
| P / Esc | 一時停止・再開 |
| R | 残機がある場合、失敗したミッションを再挑戦 |

スマートフォンでは左のスティックで移動、戦場をタッチして照準を合わせ、右のボタンで発射・地雷を操作できます。

## ルール

- 敵をすべて倒すと次のミッションに進めます。初期残機は3台で、ミッション5・10・15…をクリアするたびに1台増えます。上限はありません。
- 自分の砲弾は同時に5発まで。砲弾は壁で1回反射し、砲弾同士は相殺します。自分の跳弾にも被弾します。
- 弾道は弾速に応じて変色します。265px/秒以下は従来の色、300で黄、345で橙、390で赤、435で赤褐色、480以上で黒。中間の速度は色を補間します。配色と速度の基準は`src/terrain-render.js`の`BULLET_TRAIL_COLORS`で調整できます。
- 弾道は煙状の粒子で表示し、約0.45秒かけて広がりながら薄れます。同時に最大600粒子、描画用の画像キャッシュは最大32種類に制限しています。
- 地雷は同時に2個。約3秒のタイマー、接近、砲弾、ほかの地雷で爆発します。自分も巻き込まれます。
- 地雷はひびのある壁を壊せます。
- 穴は戦車が通れず、砲弾は反射せずに通過します。地雷で穴は壊れません。
- 地雷の爆発半径は約66.7px（従来の100pxの2/3）。戦車・壁・砲弾・地雷の誘爆に共通です。
- 爆発時は実際の爆発半径に合わせた円形の光と衝撃波を約0.45秒表示します。誘爆も地雷ごとに表示し、エフェクト終了後はデータを破棄します。
- 茶色の固定砲台、赤色の移動戦車、緑色の高速砲弾戦車が登場します。
- 撃破点は敵のプロファイルで設定します。ミッションクリアで500点。失敗したミッションのスコアは再挑戦時に戻ります。
- ベストスコアはブラウザのローカルストレージに保存します。
- 音は初期状態でOFF。画面右上から有効にできます。

## 開発

`src/engine.js` が物理・戦闘、`src/game.js` が描画・操作・サウンド、`src/style.css` が画面デザインを担当します。ステージのデータは `src/levels.js`、タイルの変換・検証は `src/tilemap.js` です。

全戦車は移動距離12pxごとに足跡を残します。足跡は時間では消えず、再挑戦・ミッション切り替え時にリセットされます。`src/track-render.js`で固定サイズのCanvasに新規分だけ描き込み、毎フレームは画像1枚を重ねます。描画済みの座標データは破棄し、未描画分も最大2,048件に制限するため、長時間プレイでも足跡の保存領域が増え続けません。

### ビジュアルレベルエディタ

`npm start` でサーバーを起動し、ゲーム右上の「レベルエディタ」、または <http://localhost:4173/editor.html> を開きます。既存の12ステージも編集できます。

1. レベルを選び、壁・壊せる壁・穴・プレイヤー・敵戦車をパレットから選択します。
2. マップをクリック／ドラッグして配置します。右ドラッグで地形と戦車を消去できます。「床」は壁や穴を消して、戦車を残します。
3. 「このレベルを試遊」で現在のレベルを、「全レベルをプレイ」でレベル一式を遊べます。ゲーム上部の「編集に戻る」から編集を再開できます。
4. 「標準レベルに保存」で **プロジェクトの `src/levels.js` をレベル一式で上書き** します。Live Serverでは保存ダイアログで `src/levels.js` を選択してください。ゲームを再読み込みすると通常プレイにも反映されます。

新規作成・複製・削除、最大40操作の取り消し／やり直し、作戦名の変更に対応します。削除や読み込みは取り消せます。標準レベルへの保存後に取り消した場合は、もう一度「標準レベルに保存」を押すとファイルも戻せます。

変更はブラウザのローカルストレージに下書きとして自動保存します。「JSONを書き出す」でバックアップ・共有でき、「JSONを読み込む」でレベル一式を置き換えられます。ブラウザのデータを消すと下書きも消えるため、残したいマップはファイルに保存してください。別のブラウザやポートでは下書きは共有されません。

試遊・標準レベルへの保存には各レベルにプレイヤー1台と敵1台以上が必要です。敵は最大32台、レベルは最大100個。壁との重なりや戦車同士の近すぎる配置は検証します。地形全体のクリア可能性は自動判定しません。

マップ上で矢印キーでマスを移動し、Enter / Spaceで配置、Deleteで消去できます。Ctrl / ⌘ + Zで取り消し、Shiftを加えてやり直します。狭い画面ではマップを横スクロールできます。

#### 範囲選択と移動

「範囲選択・移動」ツール、または `V` キーで選択モードにします。マップの空いている部分からドラッグすると矩形範囲を選択します。壁の上から選択を始めることもできます。選択範囲の内側をドラッグすると、含まれる床・壁・壊せる壁・穴・敵・プレイヤーをまとめて移動します。移動中は移動先をプレビューし、置けない場所は赤く表示します。

- 矢印キー、またはマップ上部の矢印ボタン：選択範囲を1マスずつ移動。
- Delete / Backspace、または「範囲を消去」：選択範囲の壁と戦車を消去。
- Esc、または「選択解除」：選択を解除。ドラッグ中のEscは移動をキャンセル。
- Ctrl / ⌘ + Z：移動や消去を取り消し。Shiftを加えるとやり直し。

マップの外や、選択範囲外にある別の壁・戦車に重なる場所には移動できません。移動前の範囲と移動先が重なる移動は可能です。ほかの描画ツールやレベルに切り替えると選択を解除します。

### タイルマップ形式

タイルは **20px、25行×50列**。左上のゲーム内座標は `(60, 70)`、戦場は1000px×500pxです。列は0〜49、行は0〜24で、配置した戦車はマスの中心に出現します。戦車の直径は36pxなので、通路は最低2マス必要です。既存の12ステージも新しいサイズに合わせています。

- `tiles`：25行の文字列。各行50文字。`.` が床、`#` が壁、`+` が壊せる壁、`O`（英大文字のオー）が穴。
- `player`：`[列, 行]`。編集中の未配置状態は `null`。
- `enemies`：`{ col: 列, row: 行, type: プロファイルのキー }` の配列。
- `name`：1〜60文字の作戦名。

書き出すJSONは `{ "version": 2, "levels": [ ... ] }` です。旧バージョンの53列×29行のJSONやブラウザの下書きは、読み込み時に25行×50列へ縮小変換します。薄い壁が変換時に消えないよう壁を優先して配置するため、変換で戦車と壁が近くなった場合はエディタの表示に従って調整してください。元のJSONは変更しません。

標準ステージは `src/levels.js` の `TILE_LEVELS` から読み込みます。`src/engine.js` の `LEVELS` は互換用にピクセル座標に変換したデータです。壊せる壁はタイルごとに破壊され、再挑戦時には元の状態に戻ります。

穴はエディタの「穴（弾だけ通過）」で配置します。戦車の移動・出現位置・AIの退避経路では障害物ですが、砲弾の飛行・跳弾予測・AIの射線は遮りません。壁と穴は別の衝突レイヤーで管理し、穴は砲弾の反射や地雷による地形破壊の対象にはなりません。

「標準レベルに保存」は、起動方法に応じて保存方法を切り替えます。

- `npm start`：専用サーバーのAPIでプロジェクトの `src/levels.js` に直接保存します。サーバーを更新した場合は起動し直してください。
- Live Serverなどの静的サーバー：対応ブラウザでは保存ダイアログが開きます。**プロジェクト内の `src/levels.js` を選択**して保存してください。別のフォルダーに保存すると通常のゲームには反映されません。
- ファイル選択APIを利用できないブラウザ：「levels.jsを書き出す」からファイルをダウンロードし、プロジェクトの `src/levels.js` と手動で置き換えてください。JSONのバックアップとは別形式です。

ファイル選択での保存は、ブラウザの [File System Access API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access) を使います。localhostのLive Serverで開き、画面に表示されるファイルへの書き込み許可を確認してください。保存ダイアログをキャンセルしても編集内容はブラウザに残ります。Live Serverの自動再読み込みで画面が更新された場合も、下書きから編集を再開できます。

### 敵戦車のプロファイル

`src/enemy-profiles.js` の `ENEMY_PROFILES` で種類ごとの性能と色を管理します。共通値は `DEFAULTS` にまとめ、各種類の設定で上書きします。編集後にブラウザを再読み込みすると反映されます。

AIの行動は以下の値を直接調整します。攻め方は `movement` と `strafeDistance`、射撃は `shotInterval` と `aimJitter`、回避は `dodgeRadius` と `avoidanceInterval` が主な調整箇所です。

| キー | 内容・単位 |
| --- | --- |
| `name` | 管理用の名前（画面には表示しません） |
| `moveSpeed` | 移動速度（px/秒）。`0` で固定砲台 |
| `bulletSpeed` | 砲弾の速度（px/秒） |
| `maxBullets` | 同時に存在できる砲弾の上限（整数） |
| `maxBounces` | 砲弾が反射できる回数（0以上の整数） |
| `initialShotDelay` | 出現時の発射待機時間 `[最小秒, 最大秒]` |
| `shotInterval` | 発射後の待機時間 `[最小秒, 最大秒]`。同じ値で固定間隔 |
| `activationDelay` | ミッション開始から射撃を許可するまでの時間（秒）。出現時の待機時間も満たす必要があります |
| `reactionDelay` | 視認から発射を許可するまでの時間（秒）。小さいほど反応が速く、`0`で待機なし。茶0.9、灰0.6、青緑・黄0.45、赤0.35、緑0.3、紫0.25、白0.2、黒0.15。見失うとリセット。跳弾戦車は有効な反射経路の発見でも計測開始。照準・出現時の待機・発射間隔の条件も必要 |
| `decisionInterval` | 移動方向を再判断する間隔 `[最小秒, 最大秒]` |
| `ricochetSearchInterval` | 跳弾経路を発見できないときの再探索間隔（秒）。初期値0.1。移動判断の間隔とは独立し、狙っていた経路の消失・壁の変更時は即座に再探索。有効な経路の照準更新は毎フレーム行う |
| `strafeDistance` | プレイヤーへの接近から横移動に切り替える距離（px） |
| `dodgeRadius` | プレイヤーの砲弾を検知して回避する範囲（px）。`0` で通常回避なし。自分と味方の弾への安全回避は共通 |
| `avoidanceInterval` | 弾の回避判断を再計算する基本間隔（秒）。初期値0.05、上限0.1。近距離の弾・新しい弾・反射・地形変更時は即座に再計算 |
| `wanderAngleRange` | プレイヤーが見えないときの方向変更幅（ラジアン、±値/2） |
| `blockedMoveRatio` | 実際の移動距離が予定距離のこの割合未満なら行き詰まりと判断（0〜1） |
| `blockedTurnAngle` | 行き詰まったときの方向変更角（ラジアン） |
| `blockedRetryDelay` | 行き詰まった後に方向を再判断するまでの時間（秒） |
| `score` | 撃破時の加算点 |
| `palette` | 車体・明部・暗部の3色（CSSカラー） |
| `movement` | `pursue`：追跡、`wander`：ランダム移動、`evade`：近距離では後退 |
| `aimMode` | `direct`：直接照準、`scan`：砲塔を回して探索、`ricochet`：壁の反射経路を探索。跳弾戦車は`maxBounces`以内（直射を含む）で届く有効な射撃経路を発見すると視認したと判定し、反応時間・追跡判断にも使用。経路を失うと未視認に戻る。経路探索は負荷制限の範囲で実行 |
| `aimJitter` | 直接照準の揺れ幅（ラジアン）。`0` で正確に照準 |
| `turretTurnSpeed` | 全照準モード共通の砲塔回転速度（ラジアン/秒）。`scan`では一定方向に回転、`direct`・`ricochet`では最短方向に回転して照準が合ってから発射。茶1.325、灰1.2、青緑・黄1.5、赤1.8、緑2.1、紫2.4、白2.7、黒3.2 |
| `scanTolerance` | `scan`時に発射を許可する照準誤差（ラジアン） |
| `leadFactor` | 先読みする移動速度の倍率。`0`：現在位置、`1`：等速直進を予測して迎撃。直接射撃・跳弾とも砲口位置と反射経路を含む飛行時間から計算する |
| `maxMines` | 同時に設置できる地雷数。`0` で設置なし |
| `mineInterval` | 地雷設置後の待機時間 `[最小秒, 最大秒]` |
| `mineAvoidRadius` | 地雷を避ける基本範囲（px）。`0` でも敵チームの地雷からは安全距離を取る |
| `safeMineLaying` | 黄色用の追加の先読み移動。`true` で通常移動でも壁を考慮して進路を選ぶ。設置前の味方・退路確認は全地雷持ち敵に共通 |
| `mineSpacing` | 安全な設置判断で、ほかの地雷から空ける距離（px） |
| `mineEscapeDistance` | 退避先に必要な地雷からの距離（px）。回避範囲＋10px、爆発半径＋戦車半径＋22pxを下限として使用 |
| `invisible` | `true` でプレイ中に透明化。開始待ちでは表示し、発砲・地雷設置では再表示しない。足跡は全戦車共通でミッション中ずっと残る |

例えば `red` の `moveSpeed: 135` を `160` にすると、赤い戦車の移動が速くなります。`shotInterval: [1, 1]` を追加すると発射後の待機時間が1秒になります。時間・距離・速度には0以上の数値を指定し、範囲は最小値が最大値を超えないようにしてください。

種類を追加するときは既存のエントリーを複製し、`...DEFAULTS` と `palette` を含めて定義します。`TILE_LEVELS` の敵配置 `{ col: 43, row: 6, type: 'red' }` の `type` に新しいキーを指定すると出現します。エディタのパレットにも追加する場合は `src/editor.js` の敵ツール一覧にキーを加えてください。未定義のキーはエラーになります。新しい種類も共通のAIで動作し、移動・射撃・回避をパラメータで調整できます。

### 本家を参考にした9種類

使用する敵は次の9種類です。独自の `sentry`・`scout`・`sniper` は削除し、標準レベルも茶・赤・緑へ置き換えました。旧JSON・ブラウザの下書きは読み込み時にそれぞれ `brown`・`red`・`green` へ変換します。例えば敵配置を `{ col: 43, row: 6, type: 'green' }` にすると、緑の跳弾砲台に変更できます。`CLASSIC_ENEMY_TYPES` は9種類のキーの一覧です。

| キー | 特徴 | 弾数上限 | 反射回数 | 地雷上限 |
| --- | --- | --- | --- | --- |
| `brown` | 固定砲台。砲塔を回して探索 | 1 | 1 | 0 |
| `grey` | 低速で巡回 | 1 | 1 | 0 |
| `teal` | 高速弾を撃つ防御型 | 1 | 0 | 0 |
| `yellow` | 走り回って地雷を敷設 | 1 | 1 | 4 |
| `red` | 赤／ピンク。追跡しながら連射 | 3 | 1 | 0 |
| `green` | 固定の高速弾砲台。最大2回反射で遮蔽物の向こうも狙う | 2 | 2 | 0 |
| `purple` | 高速移動、連射、跳弾狙い、地雷 | 5 | 1 | 2 |
| `white` | 透明化。発砲中も透明で、足跡や砲弾を手がかりにする | 5 | 1 | 2 |
| `black` | 最速移動、高速弾、予測射撃、地雷 | 2 | 0 | 2 |

弾数・反射回数・地雷数は [StrategyWikiの性能表](https://strategywiki.org/wiki/Wii_Play/Tanks%21) を参考にしています。敵ごとの行動の特徴は [Wii Tanks! 攻略資料](https://tanks.brightsoo.com/enemy-tanks/) も参照しています。いずれも非公式資料です。

**速度・発射間隔・AIの反応時間・色・得点は本家の内部値ではなく、このゲーム用の近似値です。** 移動速度の分類など、資料間で異なる記述がある項目もあります。地雷のタイマー・爆風・得点方式・マップもこのゲーム独自のものを共用します。

黄色は、壁や外周・ほかの戦車を考慮して退路を探し、逃げられない場所では地雷を置きません。近くに別の地雷や砲弾があるときも設置を見送ります。設置後はランダム移動より退避経路を優先し、壁に沿って曲がりながら離れます。爆発への耐性はなく、ほかの戦車の動きや砲弾による早期起爆などで巻き込まれることはあります。

敵チームはフレンドリーファイアを避けるため、直接・跳弾の射線上に味方がいる場合や、約0.75秒以内に味方が射線へ入ると予測した場合は射撃を見送ります。味方の弾は通常の回避能力に関係なく回避対象にします。地雷も所有者にかかわらず敵チームのものを警戒し、弾を避けるために味方の地雷へ突っ込む進路も避けます。

地雷を持つすべての敵が、設置前に退路と周囲の味方の約0.8秒先までの進路を確認します。近接する地雷の連鎖範囲に味方がいるときも設置を見送ります。砲弾が地雷に当たって危険な誘爆を起こす射撃も抑止します。危険な射撃は約0.1秒、危険な地雷設置は0.25秒以上待ってから再判断し、同じ確認を毎フレーム繰り返す負荷を抑えています。

これらはAIによる予防で、味方へのダメージ無効化ではありません。被弾・近接起爆・地雷の誘爆判定は残るため、プレイヤーによる起爆や予測外の急な進路変更などまで事故を完全に防ぐものではありません。

敵は発射前に約0.75秒先まで砲弾を予測し、壁の角や近くの壁から自分へ戻る射撃を見送ります。砲口が壁に埋まる射撃も防ぎます。移動中は約0.6秒先の弾道を見て、自分の弾がこれから反射する場合も含めて回避方向や一時停止を選びます。通常は回避しない赤い戦車も自分の跳弾は避けます。予測と実際の砲弾には共通の衝突処理を使っています。

回避判断は基本的に0.05秒間保持し、新しい危険が現れたときは保持を解除します。反射しない自分のロケットは予測対象から除外し、移動候補の衝突予測を複数の弾で共有します。候補は現在の方向に近い順で評価し、安全な方向が見つかれば探索を終了します。移動予測は1/30秒刻みで、実際の移動と砲弾の更新間隔は従来どおりです。

`node scripts/benchmark-avoidance.mjs` で、壁320タイル・接近弾5発などの固定条件で回避処理の平均時間と衝突判定呼び出し回数を確認できます。これは描画を含まない合成ベンチマークで、ブラウザ全体のFPSではありません。

将来の急な方向転換や長時間飛んだ弾まで完全に予測するものではなく、自分の跳弾への当たり判定も残ります。プレイヤーの射撃操作・自分の跳弾による被弾は従来どおりです。

跳弾照準（`ricochet`）は直接命中させられる場合は直接射撃を選びます。直接狙えない場合に、外周と障害物の面を使って最大2回反射の経路を探します。経路は命中までの距離を基準に、反射回数とプレイヤーと反対方向への射撃に追加の重みを付けて選び、無用な遠回りを抑えます。必要な場合は後方の壁も利用しますが、反射回数を増やすこと自体は優先しません。狙える経路がない間は発射を待ちます。予測射撃はプレイヤーの現在速度からの推定で、将来の方向転換までは予測しません。白い戦車も当たり判定は通常どおりです。
